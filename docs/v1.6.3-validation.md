## Implemented architecture

- Interview turns: bounded, compact structured output for readiness signals, fact deltas/important unknowns, one next question, information value, and draft recommendation. Retain transcript and Jira context without echoing full draft/evidence each turn. Turn budget: **1,024 output tokens**.
- Final drafting: separate structured call at convergence, user-selected eligible early draft, or hard ceiling. Distinguish known facts, suggested language, and open questions; preserve deterministic scoring and user review/edit before save. Final budget: **2,048 output tokens**. The installed SDK v1.2.1 contract limits both operations to 2,048; 4,096 is not supported by this contract.
- Readiness: explainable deterministic 0–100 score weighted toward problem, affected people, current state, impact, outcome, urgency, and constraints/unknowns; explicitly unknown and not applicable are not the same as unexplored. Show readiness separately from answer count. Offer Draft My Initiative around 65–70% if sufficient; continue only for material Initiative-level gaps. Twelve answers is an absolute ceiling, never a goal: no question 13, including on AI failure. Fallback uses accumulated context and readiness to draft or ask only one high-value question.
- Privacy: unfinished interview/draft state belongs to exactly one authenticated Matrix user, enforced on the server for read, resume, write, reset, and save, including ID manipulation. Start Over affects only that user's unfinished interview; offer explicit Resume or Start Over. Never carry another user's Jira context.
- Diagnostics: retain v1.6.2 request correlation and content-free failure metadata (request ID, category, HTTP status, duration, attempts, outcome where exposed), without duplicating Platform usage accounting or logging prompts, responses, credentials, tokens, or secrets.
