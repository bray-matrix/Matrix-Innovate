# Admin production-readiness cleanup

## Version
Innovation Hub v1.6.12 → v1.6.13. No Matrix Platform changes.

## AI administration
- Removed local provider configuration/cards, switching preview, AI_PROVIDER
  explanation, provider testing and provider test history from Admin.
- Old diagnostic endpoints return 410 without execution or history writes.
- AI Service describes Matrix Platform Shared AI Service and Anthropic Claude
  as the documented architecture from the approved release requirements, not
  a live provider observation.
- Runtime status is explicitly **Not reported**. No Claude model is hard-coded.
- SDK 1.2.1 supports generation response provider/model metadata but exposes no
  dedicated read-only current-provider/model or health endpoint. No live
  generation was used to manufacture a health result.
- Vendor AI credentials/configuration remain centrally managed by Platform.
  The UI distinguishes these from Innovation Hub's Platform application trust
  credentials; no credential values are returned.
- Rule Engine v1 is described separately as deterministic scoring, readiness,
  workflow, matching, and planning/recommendation logic, not an LLM.

## Jira and Departments
- Jira architecture and connection/discovery/mapping behavior preserved.
  Connection status, base URL, masked account, last-test display and discovery
  remain. All six existing Admin Jira write/action routes now require the same
  Platform administrator authorization as Departments. Project Jira-link
  business routes are unchanged.
- Normal users cannot use Jira mutation controls; mapping values remain visible
  in disabled inputs. Mocked Jira tests cover connection tests and redaction,
  not the availability of the live external Jira service.
- Departments retain Add/Rename/Deactivate/Reactivate and the empty-master
  defaults behavior. Compact rows use labeled action menus instead of repeating
  raw action text. Backend integration tests cover normalized duplicate rejection,
  reference propagation, inactive new-selection exclusion and history retention.
- The real `platform_administrator` role remains accepted alongside prior
  compatibility aliases; missing/unknown roles remain denied server-side.

## Policy source and read-only presentation
- Categories: static SETTINGS array in API settings source, not an editable
  seeded/database-backed category master. Initiative rows store category text.
- Statuses: static SETTINGS array representing system workflow states;
  initiative rows persist status text. No state editing added.
- Scoring weights: code-defined settings reference matching deterministic scoring
  caps 25/15/15/15/10/10/10 and penalties -10/-10. Thresholds 50/65/80 unchanged.
  Scoring and readiness implementation unchanged.
- All three are clearly labeled read-only/code-defined. No schema migration.

## Environment Initialization risk assessment
| Former action | Actual effect | Classification |
| --- | --- | --- |
| Archive sample initiatives | Snapshots then removes ALL active initiatives; no sample filter | C: potentially destructive |
| Remove sample initiatives | Deletes ALL initiatives and related records; can unlink Projects | C: potentially destructive |
| Clear validation records | Deletes validation records and checklist items | C: potentially destructive |
| Clear calculation history | Deletes calculation/audit events | C: potentially destructive |
| Initialize with no destructive selections | Writes setup flag and history | B: setup-only |
| Clear recommendation history | No-op in former implementation | B: obsolete setup control |
| View Environment History | Reads existing history without changing records | A: safe read-only utility |

The entire initialization action/wizard was removed from normal Admin. Its
execution code was retired in every environment: authenticated non-admins get
403; administrators get 410. It is not merely hidden. GET environment status and
history are retained. No production records were changed or cleanup executed.
