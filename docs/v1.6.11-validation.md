# Innovation Hub v1.6.11 — Admin master data and first-click cleanup

Before: production v1.6.10. After: v1.6.11 development. No publish, deploy or Git push.

## Departments

The existing Admin Settings Departments section now supports Add, Rename, Deactivate and Reactivate. Project Management Office is included and persisted in development. No hard-delete UI/API was added.

The master uses stable IDs and a database unique index comparing trimmed, collapsed-whitespace, case-insensitive names. Rename updates live Initiative, reviewed-Brief metadata, Resource and Project Resource Assignment department strings in one transaction, including legacy case/spacing variants. Historical version snapshots remain unchanged; no duplicate business records are created.

Active names feed existing normal selectors. Inactive historical values remain visible and may remain unchanged during an edit, but cannot be assigned as a new selection. Integration tests cover both inactive preservation and rejection of new inactive selections.

Existing production department values are not migrated by startup code. An empty master exposes original defaults plus PMO read-only. The first authorized admin write transaction initializes defaults and distinct existing Initiative/Resource/Assignment names before applying the change. Thus ordinary users are not blocked by a new setup step. The additive table/index exists in development; production schema adoption remains part of normal manual Publish.

## Authorization

Matrix SDK 1.2.1 documents signed launch identity `roles: string[]`. Hub previously discarded these claims; they now persist through its verified local session. Department mutations require Admin/Super Admin role values and return 403 otherwise. Old sessions without roles fail closed and need a fresh Platform launch. Normal users retain the existing read-only Admin Settings view but have no department maintenance controls.

**Outstanding production acceptance:** SDK documentation establishes the signed roles claim but not the actual deployed Admin/Super Admin string values. Synthetic signed admin and ordinary identities passed tests; a real Platform Admin launch must confirm the deployed role values match before claiming production admin usability. No new role assignment model or Platform code was added.

Categories remain static settings and read-only. Equivalent management is intentionally deferred.

## First-click diagnosis

See `v1.6.11-click-trace.md` for every handler branch and the browser result matrix.

Confirmed mismatch: Draft My Initiative could be visually enabled during manual Save Draft, while its handler silently returned because a save was pending. Both Draft controls now disable and show “Saving draft...” consistently with that guard. No retries or automatic repeat submissions were added.

All seven actions completed on their first valid browser click: Draft My Initiative, Word export, PDF export, Save Initiative, promotion Create Project, Confirm Jira Link and Save Draft. Real export downloads, Initiative/Project persistence and a local Jira relationship were observed. Missing required Department validation was visible and cleared on selection.

**Limitation:** The reported intermittent production first-click/second-click divergence was not reproduced. The narrower confirmed mismatch is fixed; it is not proof that every historical occurrence had that cause. Handler entry was inferred from state/network evidence rather than separately instrumented.

## Publish migration validation correction

The initial Publish diff truncated the nested normalized-name index expression even though PostgreSQL's development index definition was valid. A read-only production query confirmed Departments did not yet exist. Recomputing the diff reproduced the exact truncation; the internal parser mechanism remains unconfirmed.

The schema now uses a stored generated `normalized_name` column with the identical lower/trim/whitespace-collapse expression and a simple unique index on that column. Development was updated transactionally, creating the replacement unique index before removing the old expression index. No rows or department names were removed or changed; all eight development departments have matching generated values.

The recomputed Publish diff contains only CREATE TABLE and CREATE UNIQUE INDEX, complete SQL, no structural data loss and no warnings. Both statements were validated against a temporary development table inside a rolled-back transaction (CREATE TABLE changed only to CREATE TEMP TABLE for isolation). Case/whitespace duplicates were suppressed and rename updated normalization automatically. Library/API typechecks and all three department integration tests passed.
