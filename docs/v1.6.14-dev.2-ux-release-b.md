## Implemented

1. **Navigation:** Six initial destinations replace the always-visible secondary
   link list. Separate keyboard-operable chevrons expand Ideas & Initiatives,
   Projects, Portfolio and Administration. Group names navigate directly to their
   workspace. Child deep links open and highlight their containing section;
   current links use `aria-current`. Mobile links close the navigation drawer.
   Existing routes and role checks are unchanged.
2. **Typography:** Main body/table text 15px; ordinary supporting text and labels
   14px; primary navigation 15px, child navigation 14px; page titles 24–28px.
   Brief/export-specific typography and compact decorative badges are excluded
   from the supporting-text rules.
3. **Responsive layout:** The shared 1280px cap was replaced with a wider 1680px
   maximum and responsive horizontal padding. Data-heavy pages use the available
   width; reading/interview pages retain appropriate limits. No blanket forced
   width on all forms or reading content.
4. **Project creation:** Wider balanced required/optional columns, stacked on
   smaller screens; all existing additional fields and validation retained. The
   requested short Initiative recommendation is used verbatim.
5. **Editing panel:** Accessible right-side Sheet replaces the centered dialog.
   Full width on phones; bounded approximately half-screen on desktop. Project
   context, internal scrolling and fixed Save/Cancel footer remain visible.
   Release A opening-snapshot comparison, changed-only PATCH, null clearing,
   validation, failed-save retention, retry and duplicate-save prevention remain.
6. **Project detail:** Wider summary/workspace and readable Status & Attributes
   layout; project name/ID/type/owner, relationships, delivery health/status and
   dates presented together. Existing seven tabs and their capabilities retained.
7. **Next Steps:** Expanded once after creation. The creation marker is consumed
   without removing other query/hash/base-path information. Later visits use a
   compact reopenable section, including projects with milestones/resources.
   Session storage is only UI state, not a new data model. No automatic child
   records or governance obligations.
8. **Home:** Wider use of space, larger readable headings/support text and
   wrapping labels; existing metrics and app-wide Needs attention retained.
9. **Shared UI:** Consistent page titles, navigation, badge readability and
   portaled dialog/sheet typography. The sheet backdrop preserves visible project
   context. No new theme, dependency or full frontend rewrite.

## M365 directory investigation

Detailed evidence: [M365 investigation](m365-directory-investigation-2026-10-16.md).

- **Existing Platform endpoint:** Yes, Graph-backed tenant list/detail at
  `/api/platform/directory/users`; no supported tenant name/email search was
  found in the inspected contract/implementation.
- **Non-Platform M365 users:** Included by source design; the tenant service does
  not restrict candidates to Platform application users. Live tenant coverage
  was not tested in this session.
- **Stable identity:** `entraObjectId`; distinguish this from Platform's numeric
  `stableUserId`, display names, email and UPN.
- **Owner-field compatibility:** Current text can hold a label, but not reliable
  identity-backed ownership. It must not be silently replaced or overloaded.
- **Hub integration implemented:** NO.
- **Platform work required:** Existing list/detail reads require approved service
  access, not a new Graph registration. A scalable tenant-search picker needs
  bounded search/SDK support unless a newer supported contract is demonstrated.
- **Recommended next step:** Separately approve the search contract, existing
  workload grant, employee eligibility and additive Hub identity/snapshot mapping.
  Nothing was provisioned or modified as part of the investigation.
