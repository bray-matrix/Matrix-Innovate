**Brian rule date:** October 16, 2026 — US Central

**Development version after:** v1.6.14-dev.1  
**Production release authorization:** not granted; no publish, deploy or push performed.

## Implemented changes

- **Navigation:** Home, Ideas & Initiatives, Projects and Portfolio are primary.
  Help & guides and Administration are secondary. Existing routes and deep links
  remain unchanged. Deferred improvements links to the existing backlog tab.
- **Project creation:** Initiative-first guidance; direct creation retained for
  already-defined work. Name, project owner and a deliberate work-type choice are
  required. Description and Client are optional; all other existing fields remain
  under Additional details. There is no new wizard or backend approval rule.
- **Project editing:** Existing PATCH contract updates name, description, owner,
  supporting owners, work type, Client, Organization, Program and target date.
  Only changed fields are sent. Clearing relationships/date sends null. Unchanged
  dates are not reserialized. Unavailable existing references are preserved.
  The comparison snapshot is captured when the form opens, preventing a background
  refetch from causing untouched fields to overwrite newer saved values.
- **Next steps:** Both creation paths lead to scope/ownership, milestone and
  resource actions that open existing capabilities. No child records are created
  automatically, and the guidance is explicitly not an approval checklist.
- **Initiative workflow:** “Create linked project” replaces confusing promotion
  wording. The dialog explains retained initiative/history/link and existing Jira
  association behavior. Project creation is not approval or authorization to fund,
  implement or deploy.
- **Terminology:** Home, Board view, Develop an idea, Enter a defined idea,
  Project owner, People & capacity, Project approvals, Hub improvements,
  Deferred improvements, Release checks and Help & guides.
- **Home:** Practical starting actions, application-wide Needs attention, and
  the existing business-intake introduction. Product-maintenance metrics moved
  intact into Hub improvements instead of being removed.
- **Health:** Projects uses existing Portfolio effective-health rows joined by
  project ID. No client-side calculation or stored-health fallback. Projects,
  detail and Portfolio identify calculated values/manual overrides. Missing or
  failed health data is shown as unavailable, with retry for failed requests.
- **Save/Cancel/Delete:** Edit Cancel discards local changes. Save prevents
  duplicate requests and retains failed edits for retry. Existing immediate-save
  project controls and initiative status are labeled accurately. Review “Cancel”
  becomes “Return to interview” without changing autosave or navigation behavior.
  Project Delete is secondary and explains existing consequences before confirmation.
- **Help:** Inert Download controls removed; planned documents are explicitly
  unpublished and unavailable. Contextual explanations are not approved policy
  documents and do not implement the deferred PDF/documentation architecture.
- **Responsive corrections:** Mobile project actions wrap below the title.
  Work-type labels and descriptions no longer expand the edit dialog horizontally.
  Work type remains controlled while initially blank, and required errors clear
  as fields become valid.

## Business decisions preserved

- Initiative-first is recommended to establish scope, expected outcomes and
  business justification.
- Direct creation remains available, but is not declared the preferred long-term
  organizational policy.
- Approved initiative status is not required; no new governance gates exist.
- Organization = optional parent company/corporate entity; Client = Matrix
  customer/account; Program = related projects. These remain provisional meanings,
  not a new enforced hierarchy.
- Project owner is accountable for delivery and may also be project manager.
  No separate manager/sponsor field was added; supporting owners are not sponsors.
