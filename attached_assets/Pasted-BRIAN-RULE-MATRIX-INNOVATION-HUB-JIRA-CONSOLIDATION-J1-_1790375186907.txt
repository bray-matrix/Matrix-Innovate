==================================================
4. DATABASE MODEL — J1
==================================================

Create additive PostgreSQL entities.

A. jira_connection_state

Purpose:
Non-secret operational metadata for the configured Jira connection.

Suggested fields:
- id
- baseUrl
- accountEmailMasked or accountEmail if considered safe internal metadata
- configured
- lastTestStatus
- lastTestMessage nullable
- lastTestAt nullable
- createdAt
- updatedAt

Do NOT store API token.

B. jira_projects

Purpose:
Discovered Jira projects and mapping to Innovation Hub Projects.

Fields at minimum:
- id
- jiraProjectId
- key
- name
- projectType nullable
- syncEnabled
- projectId nullable FK -> Innovation Hub projects
- lastDiscoveredAt
- createdAt
- updatedAt

Mapping rule:

Innovation Hub Project
    1
    |
    +---- 0..N Jira Projects

Each Jira Project maps to at most one Innovation Hub Project.

If an Innovation Hub Project is deleted:
- Jira project mapping becomes NULL
- Jira discovered project remains

C. jira_status_mappings

Purpose:
Map Jira status values to canonical execution categories.

Fields:
- id
- jiraProjectId nullable
- jiraStatusId/value
- jiraStatusName
- canonicalCategory
- createdAt
- updatedAt

Canonical categories:

todo
in_progress
blocked
done

Allow NULL jiraProjectId for global/default mappings.

D. jira_field_mappings

Purpose:
Per-project Jira field overrides.

Fields:
- id
- jiraProjectId
- dueDateField nullable
- blockedField nullable
- storyPointsField nullable
- additionalMappings JSONB nullable
- createdAt
- updatedAt

Do not over-engineer custom-field support yet.

==================================================
