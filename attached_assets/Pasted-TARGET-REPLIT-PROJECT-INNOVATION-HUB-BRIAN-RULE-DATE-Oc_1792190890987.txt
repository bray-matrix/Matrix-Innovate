============================================================
2. DESIGN PRINCIPLES
============================================================

Innovation Hub is a business application used by executives,
department managers, project managers, account managers,
and other Matrix employees.

Users should not need extensive training to understand it.

Design for:

- Clear navigation
- Comfortable reading
- Efficient workflows
- Consistent interaction patterns
- Appropriate use of screen space
- Minimal unnecessary scrolling
- Clear primary actions
- Contextual secondary actions
- Responsive layouts

Avoid:

- Tiny text
- Narrow centered content columns
- Excessive whitespace around cramped forms
- Too many simultaneously visible navigation choices
- Excessive cards
- Nested boxes without clear purpose
- Unnecessarily large guidance panels
- Overuse of modals
- Dense administrative terminology

Do not sacrifice readability simply to fit more
information onto a screen.

============================================================
3. APPLICATION-WIDE LAYOUT STANDARDS
============================================================

Inspect existing shared layout components and CSS.

Determine why major pages use narrow content containers
despite substantial available desktop space.

Implement consistent responsive layout standards.

DESKTOP:

- Use approximately 85–90% of available content width
  where appropriate.
- Apply sensible maximum widths based on content type.
- Allow dashboards, project details, and data tables
  to use more horizontal space.
- Avoid arbitrary narrow max-width restrictions.
- Maintain consistent horizontal spacing.

FORMS:

- Use wider layouts when multiple fields are present.
- Avoid placing large forms inside narrow dialogs.
- Group related fields logically.
- Keep labels close to their corresponding controls.

TABLES:

- Use available width effectively.
- Maintain readable columns.
- Preserve horizontal scrolling when necessary.
- Do not compress text into unreadable columns.

MOBILE/TABLET:

- Preserve responsive behavior.
- Avoid horizontal overflow.
- Stack content where appropriate.
- Ensure navigation remains usable.
- Keep actions accessible.

Do not apply a blanket width rule that damages
simple reading pages or short forms.

Use appropriate layouts for each content type.

============================================================
4. TYPOGRAPHY AND READABILITY
============================================================

Establish consistent application-wide typography.

Recommended desktop standards:

- Body text: 14–16px minimum
- Form labels: 14px minimum
- Navigation labels: 14–15px
- Page titles: 24–28px
- Section headings: 16–20px
- Supporting text: readable without zooming

Avoid widespread use of 10–12px text.

Improve:

- Line height
- Contrast
- Label spacing
- Button readability
- Form field readability
- Card headings
- Table text
- Empty-state messages

Preserve the existing Matrix branding and color palette.

Do not introduce an unrelated visual theme.

11. MICROSOFT 365 USER SELECTION
============================================================

Brian has confirmed an important requirement:

Project owners, sponsors, and assigned resources
should ultimately be selected from actual users in
Matrix's Microsoft 365 tenant.

These users do NOT necessarily have to be registered
Matrix Platform application users.

ARCHITECTURAL REQUIREMENT:

Innovation Hub
    |
    v
Matrix Platform
    |
    v
Microsoft Graph / Entra ID
    |
    v
Matrix M365 Directory

Matrix Platform must remain the centralized owner
of Microsoft Graph credentials and integrations.

DO NOT:

- Create an Innovation Hub Graph app registration
- Request Microsoft client secrets
- Add independent Graph credentials
- Duplicate Platform authentication
- Query Microsoft Graph directly from Innovation Hub
- Require all selectable employees to be Platform users
- Introduce new Platform endpoints without approval

FOR THIS RELEASE:

Perform a read-only investigation of the existing
Platform-backed directory capabilities.

Determine:

1. Does Platform already expose a supported endpoint
   for searching M365 tenant users?

2. Does it include employees who are not registered
   as Platform application users?

3. What stable identity fields are available?

4. What information can Innovation Hub safely display?

5. Can the existing Project Owner field support
   directory-backed selection without schema changes?

6. Can Supporting Owners and assigned resources
   eventually use the same mechanism?

7. What additional Platform work, if any, is required?

If a supported endpoint already exists and can be used
without Platform changes, determine whether a bounded
Innovation Hub integration is safe.

Do not implement it if identity mapping, authorization,
or backward compatibility is uncertain.

Do not replace existing owner values or historical
records.

If Platform work is required, document the minimal
requirements for a future separate Platform task.

IMPORTANT:

Do not allow the M365 investigation to delay completion
of the visual UX improvements.
